## GitLab пайплайн состоит из четырёх стадий:
1. **verify** - проверка MR на наличие меток
2. **build** - сборка пакетов на основе меток
3. **deploy** - установка пакетов на стенд
4. **post-deploy** - выполнение дополнительных действий после установки

### Стадия verify - проверка MR

Запускается только при событии **merge_request_event**.

Основные действия:
- проверяет, что метки указаны, если меток нет, то job завершается ошибкой.

### Стадия build - сборка пакетов

Запускается после merge.

Основные шаги:
- Получение последнего смёрженного MR через GitLab API.
- Извлечение меток из MR.
- Формирование списка действий (opt:*)
  - Пример: opt:redis-clean, opt:restart-app, opt:not-install-pkgs
  - Результат сохраняется в post-deploy.env.
- Проверка метки not-install-pkgs. Если она есть, то сборка пакетов пропускается.
- Формирование списка пакетов (pkg:*)
- Архивация каждого пакета:
  - С помощью утилиты clio для Creatio.
  - С помощью утилиты ubs для BPMSoft.
- Упаковка всех архивов в packages.zip.

Артефакты:
- post-deploy.env
- packages.zip

Срок хранения: 1 неделя.

### Стадия deploy - установка пакетов

Запускается после merge, зависит от build-job.

Основные шаги:
- Загрузка переменных из post-deploy.env
- Проверка not-install-pkgs. Если она есть, то установка пакетов пропускается.
- Установка пакета packages.zip на сервер через clio или ubs.
- Проверка последней строки лога. Если содержит Error, то job завершается ошибкой.

Артефакты:
- post-deploy.env

### Стадия post-deploy - дополнительные действия

Запускается после успешного deploy, зависит от deploy-job.

Основные шаги:
- Загрузка переменных из post-deploy.env.
- Выполнение действий в зависимости от меток:
  - redis-clean - очистка Redis
  - restart-app - перезапуск веб‑приложения
